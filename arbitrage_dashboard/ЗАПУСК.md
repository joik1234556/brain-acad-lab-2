## 🚀 0. Обновить и перезапустить сайт (уже установлен)

> Путь на вашем сервере: `/root/brain-acad-lab-2`

### Полная последовательность обновления:

```bash
# 1. Перейти в папку проекта
cd /root/brain-acad-lab-2

# 2. Скачать последний код
git fetch --all --prune
git checkout copilot/update-coin-refresh-process
git pull --ff-only
git log -1 --oneline      # убедитесь что скачался нужный коммит

# 3. Установить/обновить зависимости Python
cd arbitrage_dashboard
source .venv/bin/activate
pip install -r requirements.txt
deactivate

# 4. Перезапустить сайт
systemctl restart arbitrage

# 5. Проверить что всё работает (через 5 секунд)
systemctl status arbitrage
curl -s http://localhost:8000/health
# Ожидается: {"ok":true,"uptime_s":...,"rows_cached":...}
```

### Одной командой (удобно копировать целиком):

```bash
cd /root/brain-acad-lab-2 \
  && git fetch --all --prune \
  && git checkout copilot/update-coin-refresh-process \
  && git pull --ff-only \
  && git log -1 --oneline \
  && cd arbitrage_dashboard \
  && source .venv/bin/activate \
  && pip install -r requirements.txt \
  && deactivate \
  && systemctl restart arbitrage \
  && sleep 3 \
  && curl -s http://localhost:8000/health
```

> **Почему нужен `pip install -r requirements.txt`?**
> После каждого обновления кода могут добавиться новые зависимости
> (например, `httpx` была добавлена в одном из последних обновлений).
> Запускать всегда — это безопасно и занимает ~5 секунд если всё актуально.

### Запуск как постоянный сервис (рекомендуется):

Перед созданием сервиса **замените `<ВАШ_ТОКЕН_БОТА>`** на реальный токен из @BotFather:

```bash
# Создать systemd сервис (комментарии убраны — systemd их не поддерживает в heredoc):
cat > /etc/systemd/system/arbitrage.service << 'EOF'
[Unit]
Description=Arbitrage Insights Dashboard
After=network.target redis.service

[Service]
Type=simple
User=root
WorkingDirectory=/root/brain-acad-lab-2/arbitrage_dashboard
ExecStart=/root/brain-acad-lab-2/arbitrage_dashboard/.venv/bin/python app.py
Restart=always
RestartSec=5
Environment=ENV=production
Environment=REDIS_URL=redis://localhost:6379/0
Environment=TELEGRAM_BOT_TOKEN=<ВАШ_ТОКЕН_БОТА>
Environment=TELEGRAM_BOT_USERNAME=arbitrageinsights_bot

[Install]
WantedBy=multi-user.target
EOF

systemctl daemon-reload
systemctl enable --now arbitrage
systemctl status arbitrage

# Проверить:
curl -s http://localhost:8000/health
# Ожидается: {"ok":true,"uptime_s":...,"rows_cached":...}
```

> **Ошибка "bad unit file setting"?**
> Systemd не поддерживает `#` комментарии между строками `Environment=`.
> Скопируйте шаблон выше точно (без лишних комментариев внутри `[Service]`).
> Потом: `systemctl daemon-reload && systemctl restart arbitrage`

### Nginx (чтобы сайт был доступен на порту 80):

```bash
apt install -y nginx
cat > /etc/nginx/sites-available/arbitrage << 'EOF'
server {
    listen 80;
    server_name _;   # замените на ваш домен если есть

    # SSE endpoint — отдельный блок: без буферизации, без keep-alive
    location /events {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Connection "";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_buffering off;
        chunked_transfer_encoding off;
        proxy_read_timeout 3600;
    }

    location / {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 3600;
        proxy_buffering off;
    }
}
EOF

ln -sf /etc/nginx/sites-available/arbitrage /etc/nginx/sites-enabled/
nginx -t && systemctl enable --now nginx

ufw allow OpenSSH && ufw allow 80/tcp && ufw enable
```

## ⚡ Новая архитектура: Collector + API (рекомендуется для 50+ пользователей)

> **Суть**: два отдельных процесса. Collector опрашивает биржи и пишет в Redis.
> API читает только из Redis — никакой нагрузки на CPU от бирж при запросах пользователей.

### Как это работает:

```
Биржи ──▶ collector.py ──▶ Redis (arb:snap:*) ──▶ app.py (API)
                              └──▶ arb:sse ──────▶ SSE клиенты
```

- **Collector** (1 процесс): опрашивает MEXC/Bybit/BingX каждые 30с, вычисляет спреды, пишет готовый JSON в Redis
- **API** (1+ воркеров, `COLLECTOR_ONLY=1`): никогда не ходит на биржи, читает готовый ответ из Redis за <1мс, отдаёт пользователям

### Установка (один раз):

```bash
# 1. Скопировать сервис коллектора
cp /root/brain-acad-lab-2/arbitrage_dashboard/arbitrage-collector.service \
   /etc/systemd/system/arbitrage-collector.service

# 2. Отредактировать — вставить токен бота
nano /etc/systemd/system/arbitrage-collector.service
# Замените ЗАМЕНИТЕ_НА_ТОКЕН_БОТА на ваш токен (без кавычек)

# 3. Отредактировать существующий arbitrage.service — добавить COLLECTOR_ONLY=1 + LOG_LEVEL
nano /etc/systemd/system/arbitrage.service
# Добавить в [Service]:
#   Environment=COLLECTOR_ONLY=1
#   Environment=LOG_LEVEL=WARNING
# Убедитесь что REDIS_URL=redis://localhost:6379/0 тоже есть

# 4. Загрузить и запустить оба сервиса
systemctl daemon-reload
systemctl enable --now arbitrage-collector
systemctl restart arbitrage

# 5. Проверить
systemctl status arbitrage-collector
systemctl status arbitrage
curl -s http://localhost:8000/health
# После первых 30с ожидается: "rows_cached": 50+ (данные от коллектора)
```

## ⚡ WebSocket-коллектор (рекомендуется для задержки ≤300мс)

> **Вместо REST-опроса** бирж каждые 3 секунды — постоянное WebSocket-соединение.
> Обновления цен приходят в **50–300мс**. Нагрузка на CPU и количество HTTP-запросов
> снижаются в 10+ раз.

```
MEXC  WS  ──┐
Bybit WS  ──┼──▶ in-memory prices cache ──▶ spread calc (каждые 300мс)
BingX WS  ──┘                               ──▶ Redis arb:snap:*
                                            ──▶ arb:sse pub/sub
                                                ──▶ SSE клиенты
```

### Установка WS-коллектора:

```bash
# 1. Скопировать сервис
cp /root/brain-acad-lab-2/arbitrage_dashboard/arbitrage-ws-collector.service \
   /etc/systemd/system/arbitrage-ws-collector.service

# 2. Вставить реальный токен бота
nano /etc/systemd/system/arbitrage-ws-collector.service
# Замените ЗАМЕНИТЕ_НА_ТОКЕН_БОТА

# 3. Убедиться что в arbitrage.service есть:
#   Environment=COLLECTOR_ONLY=1
grep COLLECTOR_ONLY /etc/systemd/system/arbitrage.service || \
  echo "⚠️ Добавьте Environment=COLLECTOR_ONLY=1 в arbitrage.service"

# 4. Запустить
systemctl daemon-reload
systemctl enable --now arbitrage-ws-collector
systemctl restart arbitrage

# 5. Проверить
systemctl status arbitrage-ws-collector
curl -s http://localhost:8000/health
```

### Сравнение режимов:

| Параметр              | REST-collector | WS-collector |
|-----------------------|----------------|--------------|
| Задержка данных       | 3–10 сек       | 50–300 мс    |
| HTTP-запросов/час     | ~2000          | ~5 (bootstrap only) |
| CPU collector         | ~15–25%        | ~3–8%        |
| Reconnect при обрыве  | следующий цикл | ~1–60 сек    |
| Стабильность          | очень высокая  | высокая      |

### Переменные окружения ws_collector:

| Переменная                | По умолчанию | Описание                              |
|---------------------------|-------------|---------------------------------------|
| `REDIS_URL`               | —           | Обязательно: redis://localhost:6379/0 |
| `SNAPSHOT_THROTTLE_SEC`   | `0.3`       | Мин. интервал записи в Redis (сек)   |
| `MAX_BINGX_SYMS`          | `200`       | Макс. символов BingX через WS        |
| `MAX_BYBIT_BATCH`         | `10`        | Символов в одном subscribe сообщении |
| `LOG_LEVEL`               | `INFO`      | INFO, WARNING, DEBUG                 |
