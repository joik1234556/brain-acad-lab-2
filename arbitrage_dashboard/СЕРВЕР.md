# Arbitrage Insights — Деплой на VPS (Linux сервер)

Это пошаговая инструкция для запуска сайта на Linux-сервере (Ubuntu/Debian).

> **Предполагается**: у вас есть VPS с Ubuntu 22.04 / 24.04 и root-доступ по SSH.

---

## 🚀 0. Обновить и перезапустить сайт (сайт уже установлен)

> Путь на вашем сервере: `/root/brain-acad-lab-2`

```bash
cd /root/brain-acad-lab-2
git fetch --all --prune
git checkout copilot/update-coin-refresh-process
git pull --ff-only
git log -1 --oneline

cd arbitrage_dashboard
source .venv/bin/activate
pip install -r requirements.txt   # всегда — на случай новых зависимостей

systemctl restart arbitrage

curl -s http://localhost:8000/health
# Ожидается: {"ok":true,"uptime_s":...,"rows_cached":...}
```

## 6. Настроить автозапуск через systemd

Создать файл сервиса:

```bash
sudo nano /etc/systemd/system/arbitrage.service
```

Вставить содержимое (нажмите `Ctrl+Shift+V`).
**Замените `<ВАШ_ТОКЕН_БОТА>` на токен из @BotFather перед сохранением:**

> ⚠️ Комментарии (`#`) внутри `[Service]` не поддерживаются systemd.
> Если добавите `#` внутри блока — получите ошибку «bad unit file setting».

```ini
[Unit]
Description=Arbitrage Insights Dashboard
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/root/brain-acad-lab-2/arbitrage_dashboard
ExecStart=/root/brain-acad-lab-2/arbitrage_dashboard/.venv/bin/python app.py
Restart=always
RestartSec=5
Environment=ENV=production
Environment=REDIS_URL=redis://localhost:6379/0
Environment=TELEGRAM_BOT_TOKEN=<ВАШ_ТОКЕН_БОТА>
Environment=TELEGRAM_BOT_USERNAME=arbitrageinsights_bot

[Install]
WantedBy=multi-user.target
```

> Если вы используете не root, а другого пользователя (например `ubuntu`), замените `User=root` на `User=ubuntu`.

Сохранить: `Ctrl+O` → Enter → `Ctrl+X`

Включить и запустить сервис:

```bash
sudo systemctl daemon-reload
sudo systemctl enable arbitrage
sudo systemctl start arbitrage
```

Проверить статус:

```bash
sudo systemctl status arbitrage
# Должно быть: Active: active (running)
```

Посмотреть логи в реальном времени:

```bash
sudo journalctl -u arbitrage -f
```

## 7. Настроить Nginx (reverse proxy)

Nginx принимает запросы на порту 80 и перенаправляет их на FastAPI (порт 8000).

```bash
sudo nano /etc/nginx/sites-available/arbitrage
```

Вставить:

```nginx
server {
    listen 80;
    server_name 89.167.53.202;

    # Статические файлы напрямую через nginx (быстрее)
    location /static/ {
        alias /root/brain-acad-lab-2/arbitrage_dashboard/static/;
        expires 7d;
        add_header Cache-Control "public, immutable";
    }

    # SSE (Server-Sent Events) — нужен специальный режим
    location /events {
        proxy_pass         http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header   Connection "";
        proxy_buffering    off;
        proxy_cache        off;
        chunked_transfer_encoding off;
        proxy_read_timeout 3600s;
        proxy_set_header   Host $host;
        proxy_set_header   X-Real-IP $remote_addr;
    }

    # Все остальные запросы
    location / {
        proxy_pass         http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header   Upgrade $http_upgrade;
        proxy_set_header   Connection "upgrade";
        proxy_set_header   Host $host;
        proxy_set_header   X-Real-IP $remote_addr;
        proxy_set_header   X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_read_timeout 60s;
    }
}
```

Активировать конфиг:

```bash
sudo ln -s /etc/nginx/sites-available/arbitrage /etc/nginx/sites-enabled/
sudo nginx -t          # Проверить конфиг (должно быть: syntax is ok)
sudo systemctl restart nginx
sudo systemctl enable nginx
```

Теперь сайт доступен по адресу: **http://89.167.53.202**

## 8. Настроить firewall (ufw)

```bash
sudo ufw allow OpenSSH     # SSH — обязательно, иначе потеряете доступ
sudo ufw allow 80/tcp      # HTTP
sudo ufw allow 443/tcp     # HTTPS (для будущего SSL)
sudo ufw enable
sudo ufw status
```

Раскомментируйте её (`sudo nano /etc/systemd/system/arbitrage.service`), затем:

```bash

```

## 10. (Опционально) SSL / HTTPS бесплатно через Let's Encrypt

> Требует доменное имя (не работает на голом IP).  
> Если у вас есть домен — направьте его A-запись на `89.167.53.202`, затем:

```bash
sudo apt install -y certbot python3-certbot-nginx
sudo certbot --nginx -d ваш-домен.com
sudo systemctl reload nginx
```

Certbot автоматически добавит в nginx конфиг `ssl_certificate` и редирект 80→443.  
Сертификат обновляется автоматически (cron + systemd timer certbot.timer).

### После включения HTTPS — ограничить CORS до вашего домена

В `/etc/systemd/system/arbitrage.service` добавьте в секцию `[Service]`:

```ini
Environment=ALLOWED_ORIGINS=https://ваш-домен.com
```

Затем:

```bash
sudo systemctl daemon-reload && sudo systemctl restart arbitrage
```

Без этой переменной CORS разрешает все домены (безопасно для сервера без публичного домена).

### После включения HTTPS — включить логирование в файл (опционально)

```ini
Environment=LOG_FILE=/var/log/arbitrage/arbitrage.log
```

```bash
sudo mkdir -p /var/log/arbitrage && sudo chown $USER /var/log/arbitrage
sudo systemctl daemon-reload && sudo systemctl restart arbitrage
```

Файл автоматически ротируется (макс. 10 МБ × 3 резервных копии).

## 12. Авто-обновление — сайт сам перезапускается после git pull

Скрипт `scripts/auto_redeploy.sh` проверяет изменился ли коммит после pull
и автоматически перезапускает сервис.

### Ручной запуск (вы делаете pull вручную — скрипт сам перезапустит)

```bash
cd /opt/brain-acad-lab-2

# 1. Выполните ваши команды для обновления:
git fetch --all --prune
git checkout copilot/update-coin-refresh-process
git pull --ff-only
git log -1 --oneline

# 2. Запустите скрипт авто-деплоя:
sudo bash arbitrage_dashboard/scripts/auto_redeploy.sh
```

Скрипт:
- Сравнивает HEAD до и после pull
- Если коммит изменился — устанавливает зависимости и перезапускает сервис
- Если коммит не изменился — ничего не делает (быстро, без шума)
- Пишет лог с датой, коммитом и статусом сервиса

### Полностью автоматический режим (cron — опрашивает GitHub каждую минуту)

```bash
# Откройте crontab для root:
sudo crontab -e

# Добавьте строку (проверяет и обновляет каждую минуту):
* * * * * /bin/bash /opt/brain-acad-lab-2/arbitrage_dashboard/scripts/auto_redeploy.sh >> /var/log/arb_redeploy.log 2>&1
```

Теперь достаточно сделать `git push` из любой машины — через ~1 минуту
сервер сам подтянет изменения и перезапустится.

Смотреть лог авто-деплоя:
```bash
tail -f /var/log/arb_redeploy.log
```

## Шпаргалка — полезные команды

| Действие | Команда |
|---|---|
| Статус сайта | `sudo systemctl status arbitrage` |
| Перезапустить сайт | `sudo systemctl restart arbitrage` |

| Firewall — открытые порты | `sudo ufw status` |
